# 中文核心（双栏）论文写作规范

从 `source_TAC-R2S2R.txt`（导师意见修订稿）与中文核心期刊通行要求提炼。
写新稿时逐条对照。

## 1. 结构

| 部分 | 要求 |
|---|---|
| 标题 | 中文 ≤ 25 字为佳；方法名 + 对象 + 任务。配英文标题 |
| 摘要 | 问题 → 方法 → 3 条带数字的结论 → 工具链/意义。不出现"本文将""有望" |
| 关键词 | 5–6 个，领域词 + 方法词 + 对象词 |
| Abstract / Key words | 与中文一一对应，不是机翻腔 |
| 1 引言 | 背景 → 真实痛点 → 本文研究的两个问题 → 贡献 3 条（编号列出） |
| 2 相关工作 | 按路线分节；每条写清"已有方法做到什么 + 留下什么可测缺口" |
| 3 方法 | 先给数据流总述，再分节；公式编号，每式紧跟文字解释与本文实例 |
| 4 实验 | 平台与数据 → 指标与协议 → 主结果 → 消融 → 资源消耗 → 失败归因 |
| 5 结论与展望 | 结论（带数字）+ 局限（明确写出没做什么）+ 3 条后续路线 |
| 参考文献 | 只引真实存在、确实读过的；不编卷期页码 |

## 2. 证据口径（最重要）

原稿被导师要求整改的核心就是这一条。文中任何数字必须能归入三类之一，并写明类别：

- **本文实测**：来自自己的日志，须能给出生成脚本与文件路径；
- **公开文献**：必须标注来自哪篇，且注明"任务、本体、预算不同，不可直接排名"；
- **预注册计划值 / 演示数据**：只能用于锁定协议与版式，**不得**写成结果。

禁止句式：无实测时的"显著优于""大幅提升""达到 SOTA"。
替代写法：写清协议、写清当前数值、写清还需补什么。

## 3. 语言

- 每个热门概念都要落到可观测变量：具身智能 = 视觉/语言/状态/动作闭环；
  数字孪生 = 可执行仿真 + 参数后验 + 残差回写。不堆术语。
- 一段一个论点；先结论后依据。
- 公式之后必须有"这式子在本文里具体是什么"的一句话。
- 图表之后必须有正文解读，写清横纵轴、样本量、观察到的具体数值。

## 4. 版式（build_paper.py 已实现）

- A4 双栏，栏间距 0.75 cm，页边距上下 1.9 cm、左右 1.5 cm；
- 中文宋体、西文 Times New Roman；标题与表头用黑体；
- 正文 9 pt（小五），行距固定 13.5 磅，首行缩进 2 字符，两端对齐；
- 一级标题 10.5 pt 黑体，二级 9 pt 黑体；
- 三线表：顶线 1.5 磅、栏目线 0.5 磅、底线 1.5 磅，无竖线；
- 图 200 dpi PNG，图题在图下居中 8.5 pt 黑体，表题在表上居中；
- 公式居中、编号右对齐（制表位实现）；
- 页脚居中页码。

## 5. 常见退稿点（对照自查）

1. 把回合奖励当性能指标 —— 本文已用实测速度替代；
2. 只给总体结果，没有受控偏移、消融与失败案例三层；
3. 把他人论文数字当自己的对照实验；
4. 方法写成概念堆叠，没有可执行的接口与参数；
5. 局限只写一句套话，不写具体没做什么。
