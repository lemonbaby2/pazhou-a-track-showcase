# 硬件清单与 BOM

> **口径说明**：本文分两部分。
> **A 部分（训练侧）** 是本次实验实际使用的设备，参数取自 `lscpu` / `nvidia-smi` / `/etc/os-release` 实测输出，可信。
> **B 部分（机器人本体）** 依据 Pollen Robotics 官方公开参数与仓库 MJCF 模型整理，**不是采购清单**；型号带「厂商锁定」的条目以官方为准，价格列为**量级估算**，勿直接当报价用。

## A. 训练与评测设备（实际使用）

### A.1 计算节点

| 部件 | 型号 / 规格 | 实测值 |
|---|---|---|
| 整机 | NVIDIA DGX Spark | 主机名 `spark-a8d2` |
| SoC | NVIDIA GB10 Grace Blackwell | 统一内存架构 |
| CPU | 20 × ARM Cortex-X925（aarch64），10 核/簇 × 2 簇 | 单线程 1 thread/core |
| GPU | 1 × NVIDIA GB10 | 驱动 580.159.03，CUDA 13.0 |
| 内存 | 121 GB 统一内存（CPU/GPU 共享） | 训练时常驻 ~30 GB |
| 存储 | 3.7 TB NVMe（`/dev/nvme0n1p2`） | `/` 已用 2.5 TB（71%） |
| 网络 | 千兆以太 + Tailscale | 局域网 / 远程两路 |

### A.2 软件栈

| 层 | 版本 |
|---|---|
| OS | Ubuntu 24.04.4 LTS，kernel 6.17.0-1021-nvidia |
| Python | 3.12（uv 管理） |
| PyTorch | 2.11.0+cu130 |
| MuJoCo | 3.10.0 |
| 仿真框架 | mjlab（Warp 后端，`newton_mjwarp`） |
| RL | rsl_rl（PPO） |
| 视频 | MoviePy 1.0.3 + ffmpeg 6.1.1 |
| 日志 | TensorBoard → JSON（`export_sprint_metrics.py`） |

### A.3 训练规模实测

| 项 | 值 |
|---|---|
| 并行环境数 | 4096 |
| 每轮迭代 | 24 控制步 × 4096 环境 ≈ 98 k 环境步 |
| 单轮耗时 | **9.1 s**（iter 0 为 10.1 s，稳定后 9.1 s） |
| 3000 轮总耗时 | **≈ 8.3 h**（2026-10-30 04:27 → 12:45） |
| 吞吐 | ≈ 10.8 k 环境步/秒 |
| 最优检查点 | iter 250（≈ 40 min 训练） |

> 注：512 环境时单轮并未显著变快 → Warp 的 kernel 启动与调度开销在小规模下占比过高，**并行度必须堆到 4096 才划算**。

## C. 与官方的差异（本仓只改了仿真侧）

| 层 | 是否改动 |
|---|---|
| 硬件 | ❌ 完全未改，全部实验在仿真中完成 |
| MJCF 模型 | ❌ 未改，直接使用官方 `robot/microduck/*.xml` |
| 环境配置 | ✅ 新增 `microduck_sprint_env_cfg.py`（奖励、命令、回合长度） |
| 任务注册 | ✅ 追加 2 个 `register_mjlab_task` |
| 训练/评测脚本 | ✅ 新增测速、指标导出、图表、论文生成脚本 |

**真机迁移未验证**：所有速度数字均来自 MuJoCo Warp 仿真。MJCF 含 2° 反向间隙与电池电压跌落随机化，但均未经实物校准。
