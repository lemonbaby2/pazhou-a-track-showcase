# 方案设计

## 一、设计目标

1. **平台无关**：官方 SDK 未公布也能先把任务逻辑跑通；
2. **可恢复**：任何一步失败都有明确的恢复策略，不靠人救；
3. **可复盘**：每一步、每次重试都有结构化日志，赛后能对齐评分；
4. **离线**：不依赖任何云端服务，符合现场禁网要求。

---

## 二、分层架构

```
┌──────────────────────────────────────────────┐
│  任务层  bev/task.py                          │
│  状态机 + 异常恢复 + 语音时序                  │
└───────────────┬──────────────────────────────┘
                │ 只依赖 5 个接口
┌───────────────▼──────────────────────────────┐
│  接口层  bev/interfaces.py                    │
│  Navigation / Arm / Gripper / Vision / Voice  │
└───────┬───────────────────────┬──────────────┘
        │                       │
┌───────▼─────────┐   ┌─────────▼──────────────┐
│ 仿真后端        │   │ 官方 SDK 适配器         │
│ mock_world.py   │   │ adapters/vendor_sdk.py │
└─────────────────┘   └────────────────────────┘
```

**换平台 = 换右下角那个适配器**，任务层一行不改。

## 三、状态机

```
BOOT → ANNOUNCE → NAV_PREP → DETECT
     → PICK_PLACE_1 → PICK_PLACE_2
     → NAV_GUEST → SERVE_1 → SERVE_2 → DONE
                                   ↘ ABORT（任一步不可恢复）
```

| 状态 | 退出条件 | 失败处理 |
|---|---|---|
| BOOT | 自检通过 | 直接 ABORT |
| ANNOUNCE | 播报完成 | — |
| NAV_PREP | 到达且托盘未超限 | 重试 ≤2 → ABORT |
| DETECT | ≥2 瓶 | <2 → ABORT |
| PICK_PLACE_* | 夹到并放稳托盘 | 抓取重试 ≤3；释放重复 ≤3 |
| NAV_GUEST | 到达且托盘未超限 | 倾角超限 → 调平继续；导航失败重试 ≤2 |
| SERVE_* | 放稳桌面 + 语音 | 取瓶/放稳各重试 ≤3 |
| DONE | 语音结束 | — |

## 四、异常恢复矩阵

| 故障 | 判据 | 恢复动作 | 上限 |
|---|---|---|---|
| 导航失败 | `nav.goto()` 返回 False | 回 `home` 重新定位后重试 | 2 次 |
| 抓取失败 | `gripper.close()` 返回 False | 开爪 → 回 home → 重新检测 → 重抓 | 3 次 |
| 释放失败 | `gripper.open()` 后 `is_holding()` 仍 True | 重新对准目标位姿再开爪 | 3 次 |
| 托盘倾斜 | 峰值倾角 > 阈值（默认 8°） | `level_tray` 调平 → 复位监控 → 继续 | 每次导航 1 次 |
| 超时 | 仿真时间 > 300 s | 中止并语音报警 | — |

> **倾角必须按峰值判定**：导航是连续过程，只读最后一帧会漏掉中途的瞬时倾斜。`TrayMonitor` 用 `peak_deg` 而不是 `tilt_deg` 做判据。

## 五、坐标系与标定

| 名称 | 含义 | 来源 |
|---|---|---|
| `standby` | 服务待命区 | 现场标定 |
| `prep` | 饮品备餐台 | 现场标定 |
| `guest` | 客人桌停靠点 | 现场标定 |
| `prep_bottle` | 备餐台抓取位姿 | 视觉 + 标定 |
| `tray` | 托盘放置位姿 | 标定 |
| `guest_table` | 桌面放置位姿 | 标定 |
| `level_tray` | 调平位姿 | 标定 |

仿真里的坐标只是演示值（`config/task.yaml`），**上机必须重新标定**。

## 六、感知

- 仿真：`MockVision` 直接给真值，保证无相机可跑；
- 真机：`YoloVision`（`ultralytics` + 自训练权重）替换，接口不变；
- 兜底：检测不到时，用固定抓取位姿 + 力反馈确认（需官方夹爪支持）。

---

## 七、语音

- 默认 `MockVoice`（打印 + 日志），适合 CI/录像；
- Windows 比赛电脑可切 `SapiVoice`（本地离线 SAPI）；
- 若官方给语音接口，在 `VendorVoice` 里对接，**不要用云端 TTS**。

## 八、与现有资产的关系

| 资产 | 复用什么 | 不复用什么 |
|---|---|---|
| 图灵手臂 `lingbot_real` | 抓取—放置的时序、失败重试、VLA 数据采集思路 | RealMan 专有代码、固定基座假设 |
| `MicroDuck_Task2_Deploy` | 移动机器人 `robotd` 分层、里程计、语音、部署脚本思路 | 双足形态、无夹爪结构 |
| SOP 规则引擎经验 | 状态机 + 逐条规则判定 + 日志复盘 | 工业工位专用规则 |

**可选升级**：把图灵手臂的 VLA 数据管线迁到 `Gripper` 后面，做「规则抓取为主、VLA 低置信度兜底」的双通道。

## 九、参数（`config/task.yaml`）

| 参数 | 默认 | 含义 |
|---|---|---|
| `tray.tilt_limit_deg` | 8.0 | 倾角超限阈值 |
| `tray.tilt_warn_deg` | 5.0 | 预警阈值 |
| `recovery.nav_max_retry` | 2 | 导航重试次数 |
| `recovery.pick_max_retry` | 3 | 抓取重试次数 |
| `recovery.step_timeout_s` | 45 | 单步超时 |
| `sim.*` | 见文件 | 仿真随机失败率/种子/渲染帧率 |
| `voice.backend` | mock | mock / sapi |

## 十、验证策略

1. **单元测试**（`tests/test_task.py`）：快乐路径、抓取失败、导航失败、导航中止、倾角恢复、释放重试，共 6 项；
2. **蒙特卡洛**：20 个随机种子全部成功（100%）；
3. **可视化**：`out/demo.gif`、`out/keyframes.png`、`out/timeline.png`；
4. **日志复盘**：`out/run.jsonl` 可逐事件对齐评分方向。
