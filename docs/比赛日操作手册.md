# 比赛日操作手册（90 分钟总赛时）

> 原则：**先保底一轮，再冲高分**。至少完成一轮正式运行，最多两轮，取高分、不跨轮拼接。

---

## 一、赛前清单（出发前）

- [ ] 代码已提交到本地 Git，打 tag；
- [ ] 离线依赖 wheel 齐全（PyYAML / Pillow / pytest / ultralytics 如需）；
- [ ] YOLO 权重（如需）已拷入 `assets/`；
- [ ] `config/task.yaml` 的坐标是**上一次训练时段标定**的值；
- [ ] 语音后端已设为现场可用（`sapi` 或官方接口）；
- [ ] 存储介质已按主办方要求检查；
- [ ] 一份 `README` 打印件（含启动命令与回滚步骤）。

---

## 二、90 分钟分配（建议）

| 阶段 | 时长 | 目标 |
|---|---|---|
| 入场检查 + 设备上电 | 10 min | 机器人、电脑、网络（离线）、相机、语音 |
| 现场标定 | 20 min | 3 个导航点、4 个操作位姿、夹爪阈值 |
| 单点联调 | 15 min | 语音、导航单点、夹爪空夹、单瓶抓放 |
| 全流程彩排 | 15 min | 跑 1 遍完整流程，记录失败点 |
| 正式第 1 轮 | 5 min + 缓冲 | **保底**：宁可慢，不要 abort |
| 修 + 正式第 2 轮 | 剩余 | 冲高分：修第 1 轮暴露的问题 |

> 正式运行期间**不得修改程序**；要改只能在第 2 轮开始前。

---

## 三、部署步骤（现场）

```bash
# 1. 进入工程
cd pazhou_a_beverage_service

# 2. 依赖（离线 wheel）
pip install --no-index --find-links=./wheelhouse -r requirements.txt

# 3. 自检（不动机器人）
python -m sim.run_sim --no-gif          # 逻辑自检
python -m pytest tests -q               # 单测

# 4. 真机
python -m bev.app --real                # 用官方适配器（接口公布后提供）
```

> 真机入口在接口公布后补；当前先用 `sim` 验证逻辑。

---

## 四、正式运行口令与动作

1. 裁判确认开始 → 选手在电脑上**按一次启动**；
2. 机器人**自主播报**「您好，开始为您服务」；
3. 全程**不遥控、不逐步控制、不额外提示、不改程序**；
4. 若需人工恢复：**先举手申请**，获裁判批准后在监督下复位；
5. 结束后等裁判出示分项结果，**核对签字**；有异议在 **10 分钟内**提交书面说明（注明任务编号 + 证据）。

---

## 五、两轮策略

| 轮次 | 策略 | 取舍 |
|---|---|---|
| 第 1 轮 | **保底**：速度放慢、重试次数拉满、优先完成四步 | 分数不求高，求“完整” |
| 第 2 轮 | **冲分**：修第 1 轮暴露的单点问题，适度提速 | 只改已验证的模块，不重构 |

**不要**在第 2 轮做未验证的大改——宁可拿稳定分。

---

## 六、异常处置

| 现象 | 现场动作 |
|---|---|
| 抓空 | 等程序自动重试；连续 3 次失败会 abort，举手申请复位 |
| 托盘倾斜 | 程序自动调平；若反复触发，第 2 轮降速 |
| 导航跑偏 | 程序自动重试；仍失败则举手申请人工复位 |
| 语音没响 | 不影响主体分；第 2 轮换语音后端 |
| 设备故障/危险 | **立即报告裁判**，按指令处置 |
| 电脑死机 | 重启 → 重新部署 → 用剩余赛时 |

---

## 七、签字与申诉

- 每轮结束裁判出示分项结果，队伍代表核对签字；
- 签字只确认“收到记录”，不影响时限内申诉；
- 异议须在结果出示后 **10 分钟内**提交书面说明（任务编号 + 证据）；
- 拒签由裁判注明。
