# 真机数据采集 SOP（A 赛道 · 商业饮品服务）

> 这份 SOP 的目标不是"教会采数据"，而是让**采回来的数据一定训得动**。
> 顺序不能跳：每一步的产出是下一步的输入，跳一步就在后面以 10 倍代价还回来。

## 总览：一条链，七个闸门

```
① 任务定义 ──► ② 硬件与相机 ──► ③ 标定 ──► ④ 示教采集 ──► ⑤ 质检 ──► ⑥ 归档版本 ──► ⑦ 训练与回归
   评分表        视角决定上限      数据能不能用   原始数据       废数据出局    可复现         闭环
    ↓              ↓                ↓             ↓             ↓            ↓             ↓
  技能清单       固定相机位        calib/ 带版本   episode 目录   qc_report    sha256 清单   成功率数字
```

**时间预算（按 2 人 1 机）**

| 阶段 | 一次性成本 | 每次重做 |
|---|---|---|
| ① 任务定义 | 2 h | — |
| ② 硬件与相机 | 4 h | 换机位时 |
| ③ 标定 | 3 h | 动过相机/换场地必做，约 30 min |
| ④ 示教采集 | — | 50 条 ≈ 1.5~2 h |
| ⑤ 质检 | — | 20 min（自动 + 抽检） |
| ⑥ 归档 | 1 h | 5 min |
| ⑦ 训练回归 | — | ACT 2~4 h + 回归 1 h |

## ① 任务定义：从评分表倒推技能清单

**不要**上来就想着"我要采一个端到端的 VLA"。评分表拆得越细，你的数据越好用。

按赛题 100 分 = 场景操作 75 + 任务五 15 + 任务六 10，倒推出必须被数据覆盖的技能：

| 技能 | 对应状态机 | 单条时长 | 目标条数 | 判成功条件 |
|---|---|---|---|---|
| 移动到备餐位 | `NAV_PREP` | 5~8 s | 30 | 到位误差 < 5 cm / 3° |
| 识别并抓取第 1 瓶 | `PICK_PLACE_1` | 6~10 s | 50 | 夹爪夹住且不滑落 |
| 抓取第 2 瓶（位置偏移） | `PICK_PLACE_2` | 6~10 s | 50 | 同上 |
| 端托盘移动 | `NAV_GUEST` | 8~12 s | 30 | 全程倾角 < 8° |
| 上饮到桌面 | `SERVE_1/2` | 5~8 s | 50 | 瓶底落桌且夹爪张开 |
| 倾角恢复 | 恢复分支 | 3~5 s | 20 | 调平后重新到位 |
| 抓取失败重试 | 恢复分支 | 5~8 s | 20 | 第 2/3 次夹住 |

**规则：一条 episode 只做一个技能，5~15 秒。** 超过 30 s 的段必须拆——不是"数据少一点"，是"模型学不动"。

**验收**：一张技能清单表，每行有「指令文本 / 时长范围 / 目标条数 / 判成功条件」。
指令文本一旦定下**不许改**，改了等于换任务，旧数据全废。

## ② 硬件与相机：视角决定上限

### 相机配置（三路，按重要性排）

| 位置 | 作用 | 是否进模型 | 分辨率 | 备注 |
|---|---|---|---|---|
| **腕部**（eye-in-hand） | 抓取精度全靠它 | ✅ 必进 | 640×480@30 | 跟着夹爪动 |
| **头部**（第一视角） | 全局场景、瓶子在哪 | ✅ 必进 | 640×480@30 | 固定机身 |
| 第三人称/俯视 | 只用于**复盘和标注** | ❌ | 1280×720 | 不参与训练，省显存 |

### 硬性要求

- **USB 相机必须直连主机，不许过 hub**——过 hub 掉帧是最常见的数据杀手
- 优先**全局快门**：轮式底盘移动时卷帘会出果冻效应
- 相机用**打印夹具 + 定位销**固定，标记基准线；一旦固定，**全程不许碰**
- 光照先定死：开哪几盏灯、窗帘拉不拉，写进 `meta.json` 的 `lighting` 标签
- 底盘/手臂急停可用，且**急停按钮在操作员手边**

**验收**：三路相机同时录制 60 s，掉帧率 < 1%（用 ⑤ 的质检器验）。

## ③ 标定：数据能不能用的分水岭

| 标定项 | 方法 | 验收 |
|---|---|---|
| 相机内参 | 棋盘格 ≥ 20 张，不同角度 | 重投影误差 < 0.5 px |
| 手眼外参 | eye-in-hand：标定板 + 多姿态求解 | 抓取点误差 < 5 mm |
| 机械臂零位 | 回零后读编码器 | 重复定位 < 1 mm |
| 夹爪开合行程 | 全开/全闭记录 | 开合到位、无卡滞 |
| 底盘里程计 | 直行 1 m、原地转 90° 各 3 次 | 直行误差 < 2 cm，转角误差 < 2° |
| 托盘水平零位 | 空托盘静置读 IMU | 零点 < 0.5° |

产出目录（**必须带日期**）：

```
calib/
  2026-11-08/
    cam_intrinsics.yaml
    hand_eye.yaml
    arm_zero.json
    odom_check.csv
    tray_zero.json
```

**验收**：`calib/<日期>/` 齐全，且 `meta.json` 里能查到用的是哪一版。
**动过相机 = 全部重做**，别省这 30 分钟。

## ④ 示教采集：核心动作

### 采集方式（按可用性排）

1. **主从遥操作**（leader-follower）：最稳，动作最自然，优先
2. **VR 遥操作**（Quest 3）：XLeRobot / reBot 都在用，采数快
3. **手柄 / 键盘**：兜底，动作会抖，只用于恢复类短片段

### 采集纪律

| 项 | 要求 | 原因 |
|---|---|---|
| 单条时长 | 5~15 s | 太长模型学不动 |
| 首帧 | **静止 0.5 s** | 给模型一个明确起点 |
| 末帧 | **静止 0.5 s** | 否则末态抖动被当成动作 |
| 中断 | **一条废了整条重录**，不要剪接 | 剪接会破坏时间连续性 |
| 失败样本 | **单独标记 `success=false`** | 恢复策略要用，但不能混进成功集 |
| 多样性 | 瓶子位置 ±3 cm、起始位姿 ±5°、光照 2 种 | 50 条干净 > 200 条同一配置 |

### 每采一条要做的事（清单）

```
□ 摆好物体（按预设扰动表，不是随手放）
□ 喊一声"开始"→ 启动录制 → 执行 → 结束 → 停止录制
□ 立刻回放 3 秒，确认画面没糊、夹爪真夹到
□ 打成功标记（True/False）+ 一句话备注
□ 记一行到采集台账：条号 / 技能 / 扰动 / 光照 / 成败 / 备注
```

### 用本仓库采集（零依赖，现场保底）

```bash
# 仿真演练完整链路（备赛期先跑这个，把流程走顺）
python -m scripts.record_episode --out data/raw --episodes 3 --seed 1 --min-frames 4 --qc

# 真机：在 bev/adapters/vendor_sdk.py 醒来后，读 (关节角, 夹爪, 时间戳) 喂给
#   rec.add_frame(state=[...], t=clock.now())
```

**验收**：每个技能达到目标条数；采集台账与 `meta/episodes.jsonl` 条数一致。

## ⑤ 质检：采完 5 分钟内必须知道好坏

```bash
# 仿真/抽象动作空间（不校验关节量纲）
python -m scripts.check_dataset --root data/raw --min-episodes 10

# 真机（关节角为弧度时开 --joint-limit）
python -m scripts.check_dataset --root data/raw --joint-limit 3.2 --min-episodes 50 --fail-on warn
```

自动判据（`bev/dataset.py`）：

| 码 | 级别 | 触发条件 | 处理 |
|---|---|---|---|
| `E_EMPTY` | 错误 | 0 帧 | 重录 |
| `E_LONG` | 错误 | > 30 s | 拆段重采 |
| `E_TIME_BACK` | 错误 | 时间戳回退 | 检查时钟/多线程写 |
| `E_GAP` | 错误 | > 5% 帧间隔 > 3×周期 | 查 USB / 掉帧 |
| `W_GAP` | 警告 | 少量丢帧 | 可接受，记录 |
| `W_STATIC` | 警告 | 动作 std ≈ 0 | 空录或死帧，重录 |
| `W_SPIKE` | 警告 | 单帧动作跳变 | 查标定/丢帧 |
| `W_UNIT` | 警告 | 关节值 > 3.2 rad | **把度当弧度了** |
| `W_SHORT` | 警告 | < 1 s | 信息量不足 |

**人工抽检 20%**：只看两件事——① 画面里夹爪确实夹到物体；② 轨迹连贯没有瞬移。
（RealFactory-Ego-Data 的做法更狠：手部检测率 < 50% 的片段直接丢，可以照搬）

**验收**：`out/qc_report.json` 中 `errors == 0`；抽检通过率 ≥ 95%。

## ⑥ 归档与版本：为了三天后还能复现

```
data/
  raw/
    meta/info.json            # 任务/帧率/相机/代码 commit
    meta/episodes.jsonl       # 每条 success、帧数、时长、sha256
    episodes/episode_XXXXXX/{frames.jsonl, meta.json}
  released/
    bev-2026-11-08-v1/        # 质检通过的冻结集，只进不改
      manifest.json           # 文件清单 + sha256 + 条数 + 技能分布
```

**铁律**

- **视频与轨迹不进 git**（已在 `.gitignore`），git 只存 manifest 与 sha256
- 每次冻结打一个 tag：`data-v1` / `data-v2`，训练配置里写清楚用哪一版
- `meta/info.json` 里的 `code_commit` 会自动记录——出问题能倒查当时跑的哪版代码

**验收**：`manifest.json` 里 sha256 全齐；`git tag` 能看到数据版本。

## ⑦ 训练与真机回归：拿数字说话

```bash
# 1) 转 LeRobot 格式（路径 A）；或用 lerobot-record 直接采，跳过转换
# 2) 训 ACT（先用小数据确认链路通）
lerobot-train \
  --dataset.repo_id=<你的>/bev-pick-v1 \
  --policy.type=act \
  --output_dir=outputs/train/act_v1 \
  --job_name=act_v1 \
  --policy.device=cuda \
  --wandb.enable=False

# 3) 真机回归：固定初始位姿，跑 10 次统计成功率
lerobot-record --policy.path=outputs/train/act_v1/checkpoints/last/pretrained_model \
  --dataset.repo_id=<你的>/bev_eval_v1 --dataset.episode=10 \
  --dataset.single_task="把第 1 瓶饮品放到客人桌面"
```

### 回归纪律

- **固定初始位姿**（地贴标记），每次同一位置起，否则数字没法比
- 每次回归跑 **10 次**起，记录成功率，不要"看着还行"
- 失败案例单独存，进下一轮训练集（**难例回灌**）

| 指标 | 目标 | 说明 |
|---|---|---|
| 单技能成功率 | ≥ 80% | 低于它别串全流程 |
| 全流程成功率 | ≥ 60% | 5 分钟内完成，2 瓶都上桌 |
| 最大托盘倾角 | < 8° | 超了就是 0 分 |
| 单轮耗时 | < 300 s | 赛题硬上限 |

**验收**：一张回归表（日期 / 数据版本 / 模型 / 10 次结果 / 失败原因分类）。

## 常见坑（都是踩过的）

| 坑 | 现象 | 对策 |
|---|---|---|
| 相机过 hub | 随机丢帧，`E_GAP` 一堆 | 直连主机 |
| 采集中途暂停 | 数据集的 mean/std 算错 | 一条废了整条重录 |
| 后期剪接 | 时间戳断裂，训出来抖 | 禁止剪接 |
| 把度当弧度 | 关节值几百，`W_UNIT` 报错 | 统一用 rad |
| 光照变了 | 真机成功率断崖 | 固定光照，写进标签 |
| 只采成功样本 | 遇事就卡死 | 失败样本单独标，用于恢复策略 |
| 训练集=验证集 | 数字虚高 | 留 10% 不参与训练 |
