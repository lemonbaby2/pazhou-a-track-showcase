## 一、这是什么题

**应用场景**：商业服务。
**竞赛方式**：统一平台、自主实操。
**一句话任务**：机器人夹着空托盘从待命区出发，去备餐台把 2 瓶水装进同一个托盘，端着托盘走到客人桌，再把两瓶水逐份放到桌上并语音通知。

**关键点**：这不是「算法刷榜」，是**在主办方统一平台上做二次开发**——导航、机械臂、夹爪、视觉、语音的底层接口主办方给，选手写的是**任务编排、感知调用、动作调整、异常恢复、部署**。

---

## 二、硬约束（工程必须遵守）

| 类别 | 约束 |
|---|---|
| 平台 | 统一轮式人形：轮式底盘 + 人形半身 + 双指夹爪；主办方提供比赛电脑、场地地图、预置软件环境 |
| 接口 | 主办方提供基础导航、机械臂、夹爪、视觉、语音接口；**不提供能直接完成整套赛题的程序** |
| 时间 | 每队**总赛时 90 分钟**（含部署、调试、正式运行）；单轮**规定用时 5 分钟**，超时可继续，但本轮最长运行时间或剩余总赛时先到即结束 |
| 轮次 | 至少 1 轮、最多 2 轮；**取较高分，不跨轮拼接** |
| 评分 | 基础任务 100 分 = 场景操作 75 + 任务五 15 + 任务六 10 |
| 现场 | **离线**；禁止联网求助、禁止云端 AI；代码可提前准备，经检查的存储介质导入 |
| 禁止 | 绕过安全限位、改动未开放系统、增加未经许可硬件 |
| 操作 | 运行期间**不得遥控、逐步人工控制、额外提示目标或修改程序**；需人工恢复须举手申请，获准后在监督下复位 |

> 对工程的含义：所有依赖必须**离线可跑**；不能把大模型 API 放进运行回路；程序必须**一次启动、全自主**。

## 三、场景与道具

| 位置/物品 | 说明 |
|---|---|
| 服务待命区 | 机器人初始位置，**赛前已夹稳空托盘**；通道不得有额外障碍 |
| 饮品备餐台 | 摆放 **2 份瓶装水**（D1、D2）；空托盘不放在备餐台 |
| 客人用餐桌 | 设机器人停靠区；饮品最终放在客人桌面 |
| 服务通道 | 连接待命区、备餐台、客人桌；地面标识统一，**禁止人工引导** |
| T1 服务托盘 | 运行前可人工辅助夹稳，**运行中由机器人持续稳定夹持** |

**红线**：
- 不得用**底盘置物架**承运托盘；
- 不得**直接手持饮品**从备餐台送到客人桌（必须先装盘、端盘）。

---

## 四、任务流程（四步）

1. **启动服务**：待命区，裁判确认开始后计时；选手通过电脑启动流程；机器人**自主播报**开始服务。
2. **备餐装盘**：导航到备餐台，**依次抓取 2 瓶**放到托盘（托盘已持稳且为空，不得人工预装）。
3. **端盘配送**：**持续夹稳托盘、保持不倾斜**，自主导航到客人桌停靠区；不得放到底盘置物架。
4. **上饮与通知**：从托盘**逐份**取出 2 瓶，平稳放到桌面；**语音告知已送达**并结束；无需返回待命区。

## 五、评分方向

| 方向 | 含义 | 工程落点 |
|---|---|---|
| 启动与定位 | 能否按口令启动、初始定位是否准 | 启动状态机 + 首段导航 |
| 饮品抓取与装盘 | 2 瓶是否都抓到、是否稳放托盘 | 抓取重试 + 释放重试 |
| 端盘导航配送 | 托盘是否稳、路线是否到点 | 倾角监控 + 导航重试 |
| 桌面上饮与语音 | 是否逐份上桌、是否语音通知 | 上饮状态 + 离线 TTS |
| 任务完成情况 | 四步是否都完成 | 状态机终态 |
| 过程稳定性 | 有没有抖、掉、重复动作 | 重试/恢复计数与日志 |
| 职业素养与操作规范 | 是否按规程、异常是否申请复位 | 标准化操作 + 日志复盘 |

> **任务五（15 分）、任务六（10 分）的量化条件在「评分细则」里，本任务书未展开。** 本工程按「稳定性 + 操作规范 + 异常恢复」做合理假设，见 `docs/评分对齐表.md`，细则公布后需逐条对齐。
