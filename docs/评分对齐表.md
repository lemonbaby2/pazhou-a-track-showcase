# 评分对齐表

> 依据：A 赛道初赛任务书的「评分方向」。
> ⚠️ **任务五（15 分）、任务六（10 分）的量化条件在《评分细则》里，任务书未展开**；下表对这两项做的是**合理假设**，细则公布后必须逐条重对齐。

---

## 一、场景操作（75 分）

| 评分方向 | 我们的实现 | 代码位置 | 可验证证据 | 风险 |
|---|---|---|---|---|
| 启动与定位 | 一次启动 → 自动播报 → 导航到备餐台 | `task.py: ANNOUNCE, NAV_PREP` | `run.jsonl` 的 `announce` / `nav_ok` | 现场标定误差 |
| 饮品抓取与装盘 | 逐瓶抓取 → 抬升 → 放托盘，抓取重试 3 次 | `_pick_and_place` | 2×`grasp_ok` + 2×`place_ok` | 夹爪反馈阈值 |
| 端盘导航配送 | 端盘导航 + 峰值倾角监控 + 调平恢复 | `_nav`, `tray.py` | `max_tilt_deg`、`tilt_exceeded`/`tilt_recovered` | 加减速过猛 |
| 桌面上饮与语音 | 逐份取瓶 → 放桌 → 语音通知 | `_serve` | 2×`served` + 2 条 `say` | 现场噪声 |

## 三、过程稳定性

| 指标 | 我们的度量 | 目标 |
|---|---|---|
| 导航重试 | `stats.nav_retries` | 越少越好（0 为佳） |
| 抓取失败 | `stats.grasp_failures` | ≤1 |
| 放置重试 | `stats.place_retries` | ≤1 |
| 倾角恢复 | `stats.tilt_recoveries` | 0 为佳；>0 必须有恢复成功 |
| 最大倾角 | `stats.max_tilt_deg` | 尽量 < 5°（阈值 8°） |

> 20 个随机种子实测全部成功（100%），其中若干次触发倾角/抓取恢复并成功自愈。

## 四、职业素养与操作规范

| 要求 | 我们的做法 |
|---|---|
| 运行期间不遥控/不逐步控制 | 程序一次启动，全自主 |
| 需恢复时先举手申请 | 手册明确写入（`docs/比赛日操作手册.md`） |
| 不绕过安全限位/不改未开放系统 | 只调用官方接口，不碰底层 |
| 可复盘 | 全事件 JSONL 日志 |

## 五、任务五 / 任务六（15 + 10 分，待细则）

**任务书原文未给出量化条件**，仅能推断其考查「任务完成质量 / 稳定性 / 规范」。本工程的假设与准备：

| 假设方向 | 可能的考查 | 我们的准备 |
|---|---|---|
| 稳定性 | 是否洒、是否掉、是否重复动作 | 倾角监控 + 重试上限 + 日志 |
| 效率 | 单轮用时 | 导航 24 s 级（仿真），真机可调 |
| 规范 | 是否按规定流程、是否申请复位 | 手册 + 状态机严格四步 |
| 异常处理 | 失败后能否自恢复 | 6 项单测覆盖恢复路径 |

> 细则公布后，把对应量化项补进 `config/task.yaml` 与 `stats`，并在 `run.jsonl` 里加字段。
